# 本地家庭虚拟助手

一个部署在本地电脑、具有稳定人格的家庭虚拟助手，用于管理智能设备、日常聊天和回答问题，并在获得同意后识别家庭成员、记住各自的生活习惯。

同时将其作为研究平台，探索语言理解、规则推理和事实知识的解耦。**当前复用现有模型，并没有从大模型权重中剥离知识，也没有训练新模型。**

> 当前状态：优先开发不依赖设备的人格与聊天，已支持结构化人格和手动会话快照，并保留本地知识库与规则实验。开发进度见 [TODO.md](./TODO.md)；真实模型和设备仍需本机联调验收。

## 当前可用功能

- 通过本机 Ollama 进行文字聊天，自定义名字与人格，保留最近 10 轮会话。
- 结构化人格支持名字、性格特征、语气、详略、幽默和表达边界，聊天与知识问答使用同一个当前人格。
- 默认不落盘；可显式保存、恢复、删除最近 10 轮普通聊天的人格与上下文快照。
- 通过 Home Assistant 查询白名单设备，显式开关灯或风扇，每次控制均需输入 `yes` 确认。
- 聊天与设备命令隔离：自然语言聊天不自动执行设备操作，设备状态也不自动发送给模型。
- 本地 SQLite 文档库支持导入、更新、检索、来源引用和删除，通过 `/ask` 进行检索增强问答。
- 显式规则独立于模型求值，区分真、假、未知和冲突；模型可生成候选规则，但不会自行保存、启用或执行。
- 仅支持可信本地操作员；尚无语音、成员认证、个人偏好记忆或自动化执行。

## 启动

需要 Python 3.10+ 和支持 FTS5 的 SQLite（常见 Python 发行版已内置），应用和测试仅使用标准库，无需安装 Python 依赖。

1. 安装并启动 Ollama，根据本机内存选择并下载适合的模型，例如 `ollama pull qwen3:8b`。模型由用户单独安装，本项目不会自动下载模型。
2. 创建本地配置：

   ```sh
   cp config.example.json config.local.json
   ```

3. 编辑 `config.local.json` 中的 `name`、`persona` 和 `model`。`model` 必须与已下载模型名称一致；`ollama_url` 仅接受本机根地址，默认 `http://127.0.0.1:11434`。
4. 启动终端助手：

   ```sh
   python3 assistant.py
   ```

也可使用 `python3 assistant.py --config /path/to/config.json` 指定配置。输入 `/help` 查看命令，`/reset` 清空会话上下文，`/quit` 退出。默认退出后不会保存聊天；只有显式确认 `/save` 才会保存快照。每条消息最多 8000 个字符。

**现在无需 Home Assistant 或智能设备。** 保持 `ha_url` 为 `""`、`allowed_entities` 为 `[]` 即可，不需要 `HA_TOKEN`。

### 本地聊天准备检查

在终端运行 `ollama serve`（或启动已有的 Ollama 应用），让服务在本机运行。如果应用已经启动，不需要再运行一个服务进程。在另一个终端用 `ollama list` 检查模型，必要时执行 `ollama pull qwen3:8b`，或将配置中的模型改为已有模型。

启动助手后输入：

```text
/status
你好，我们随便聊聊吧
/history
```

`/status` 检查服务和配置模型是否存在，不会生成回复，也不下载模型；“已安装”不代表模型已经完成加载或实际生成验收。连接失败会明确提示，助手仍可运行帮助、人格管理、离线检索和规则命令。

## 人格与会话

### 结构化人格

原来的 `config.local.json` 中 `name` 和 `persona` 继续有效。不指定人格文件时，会将它们转换为默认结构化人格，不修改原配置。

若希望独立维护人格：

```sh
cp persona.example.json persona.local.json
python3 assistant.py --persona persona.local.json
```

编辑 `persona.local.json` 中的名字、描述、性格特征、语气、欢迎语和表达边界。`verbosity` 为 `brief`／`balanced`／`detailed`，`humor` 为 `none`／`light`。名字最多 80 字符，描述最多 2000 字符，文件最多 100 KB；未知字段和非法取值会报错。

```text
/persona
/persona persona.local.json
```

运行时切换需要输入 `yes`，并清空旧聊天上下文，避免混入上一个人格；已保存快照不变。切换只影响当前进程，下一次启动仍由启动参数和配置决定。欢迎语来自本地配置，不是模型生成结果。

人格是表达设定，不是事实数据库或权限。核心提示要求自然共情、不冒充真人、不虚构现实经历，不会因人格变化获得设备权限。风格通过提示词引导，不能保证模型每次严格遵守；实际稳定性需要本地模型验收。

### 手动会话快照

```text
/save 周末聊天
/sessions
/resume 上一步显示的会话ID
/delete-session 会话ID
```

- 保存、恢复、删除均需输入 `yes`；不做自动保存或启动时自动恢复。
- 每次保存是独立快照，仅包含**当前最近 10 轮完整普通聊天**和当前人格，不是完整聊天档案，也不是成员习惯或长期偏好记忆。后续新消息不会更新旧快照。
- `/history` 查看当前上下文；`/reset` 清空内存上下文，不删除已存快照。删除快照不清空当前已恢复的上下文。
- 恢复会替换当前人格和聊天上下文，但不改变当前模型、设备配置或权限；也不会恢复 `system` 或工具角色消息。
- 知识问答、检索片段、规则和设备命令不进入普通聊天快照，避免已删除的知识从历史中自动重放。普通聊天中由用户主动输入的信息仍可能被保存，确认前请自行检查。
- 快照最多 256 KB；只接受 1 到 10 轮交替的用户／助手消息。超限或损坏时显式拒绝，不截断后假装保存成功。

默认保存在 `data/chat.sqlite3`，随 `--data-dir` 改变，与知识库分开。文件被 Git 忽略，但**明文保存且没有成员隔离或加密**，只供可信本地账户使用，暂不保存敏感信息或他人私密对话。删除不保证磁盘取证级擦除。

## 外挂家庭知识

目前是**词法检索 RAG 基线**：UTF-8 文档分为最多 600 字符、重叠 100 字符的片段，使用 SQLite FTS5/BM25 检索；中文使用双字切分，并索引单字。不使用向量模型，因此同义改写可能漏检。每次最多取 4 条证据，不会把整个知识库发送给模型。

```text
/ingest examples/household.md
/knowledge
/search 云灯在哪里
/ask 云灯在哪里
```

- `/ingest` 是本地操作员显式批准导入，只接受 `.txt`、`.md`，单个文件不超过 1 MB；带空格路径使用成对引号。
- 文档 ID 根据绝对来源路径生成；相同路径重复导入不变内容不会增加版本，内容变化则递增版本、替换旧索引。重命名后的文件视为新来源。
- `/search` 直接显示证据，不调用模型；`/ask` 将问题和检索片段发给本机 Ollama，要求结构化回答和引用。需要支持 JSON schema 结构化输出的 Ollama 版本和模型。
- 无命中时不调用模型，明确说明缺少证据；引用缺失或不属于本次证据时拒绝展示回答。引用格式为 `文档ID:r版本:c片段序号`。
- 引用校验只能验证引用存在，**不能保证回答被原文蕴含，也不能完全阻止提示注入**。重要信息仍应核对原文；当前没有自动消解文档冲突的能力。
- 普通聊天不读取文档；`/ask` 不携带普通聊天历史，也不会把证据或回答加入普通聊天历史，减少已删除知识被上下文继续引用的问题。
- `/forget 文档ID` 在输入 `yes` 后删除文档及索引，不删除原文件，不训练或修改模型，也不保证磁盘取证级擦除。

默认数据库是被 Git 忽略的 `data/knowledge.sqlite3`，可用 `--data-dir 路径` 更改目录。SQLite 为明文存储，依赖本机目录权限保护。导入的原始文件不一定被 Git 忽略，私有资料应置于 `data/` 等忽略目录，不能提交到仓库。

**当前仅导入经人工确认可供此终端访问的非私密资料，不导入成员私人记忆或敏感信息。** 成员隔离和授权撤回尚未实现，不得把此终端作为共享网络或语音入口。文档只作为资料，不授予设备权限；实时状态仍应通过 `/state` 查询。

## 规则与知识分离实验

先运行不依赖模型的规则样例：

```text
/reason examples/rules.json examples/facts.json
```

规则与事实在两个文件中，均不超过 100 KB。规则采用 `version: 1`：

- 每条规则只包含 `id`、`when`、`suggestion`。
- `when` 支持 `{"fact": "名称"}`、`{"all": [...]}`、`{"any": [...]}`、`{"not": {...}}`。只支持布尔命题，不支持代码、算术、任意工具调用或设备动作。
- 事实文件为 `{"facts": {"名称": true}}`；值允许 `true`、`false`、`null` 和 `"conflict"`。缺失项与 `null` 都表示未知，而不是假。
- 规则求值遵循三值逻辑的真／假／未知行为，并保守扩展冲突传播：任何被访问条件出现冲突，整条规则输出冲突，即使另一分支已经可决定结果。
- 仅状态为 `true` 时输出建议；其他状态不输出建议。报告包含表达式及所用事实的状态，不会执行建议。
- 不执行规则链式推导；`"conflict"` 需要事实提供者显式标注，不会自动从文档检测。事实快照当前由操作员提供，不能视为实时传感器数据或设备授权。

模型辅助的语言理解入口：

```text
/propose 如果书房有人、光线暗且确定没有人在睡觉，就建议补光
```

该命令要求模型生成符合规则 schema 的候选 JSON，并进行同样的严格校验；输出仅显示在终端，不写文件、不启用、不执行。应人工核对否定含义、事实名称与实际事实文件的映射，再单独保存为规则文件并使用 `/reason` 验证。即使 JSON 合法，也不代表语言理解正确。

表达式限制为 8 层、64 节点，每个 `all`／`any` 最多 16 个条件，每个文件最多 32 条规则。重复 ID、重复 JSON 字段、未知运算符、额外的动作字段和非法事实类型都会显式报错。

### 双轨研究路线

1. **应用轨**：本地人格与会话 → 外挂知识 → 成员授权和偏好记忆 → 语音 → 经确认的习惯辅助。
2. **研究轨**：受限规则表示与词法检索基线 → 虚构世界评测 → 比较模型、RAG 和显式推理 → 文献调研与专用模型实验。

这里“分离”的是职责和数据权威，不是让模型完全不含知识：语言理解核心仍携带预训练概念，具体事实和可变规则放在外部；人格控制表达风格，不参与事实判定或权限授予。

当前测试验证了换事实、换规则、条件组合、未知与冲突处理，**不是神经模型组合泛化的实验结果**。后续需要独立的数据集、模型基线和准确率、事实依赖性、延迟、内存测量，再评估蒸馏、规则归纳或新训练目标；不预设架构具有研究新颖性。

### 可选：接入 Home Assistant

不接入设备时保留 `ha_url` 为空、`allowed_entities` 为空列表即可使用聊天功能。

1. 在本地配置中填写 Home Assistant 根地址，例如 `http://192.168.1.2:8123`。地址只支持 HTTP(S) 根路径，不支持带路径前缀的反向代理。
2. 将允许操作的实体 ID 加入 `allowed_entities`，例如 `["light.living_room", "fan.bedroom"]`。只支持灯和风扇，禁止门锁、安防、通用开关等其他设备类型；添加前应人工确认设备和场景确实低风险。
3. 在 Home Assistant 为专用的非管理员账户创建长期访问令牌，并通过 `HA_TOKEN` 环境变量传入。不要写入配置、聊天或提交到 Git；macOS 默认 zsh 可使用以下方式避免把令牌直接写进命令历史：

   ```zsh
   read -rs 'HA_TOKEN?Home Assistant token: '
   export HA_TOKEN
   printf '\n'
   python3 assistant.py
   unset HA_TOKEN
   ```

4. 使用设备命令：

   ```text
   /devices
   /state light.living_room
   /on light.living_room
   /off fan.bedroom
   ```

`/devices` 仅查询白名单，不获取全屋实体列表。操作前会检查状态，不可用或未知时拒绝控制。操作后显示 Home Assistant 上报的状态，不把接口接受请求等同于物理动作完成；结果不确定时不要盲目重试。

Home Assistant 流量会发送到你配置的地址；跨不可信网络时应使用 HTTPS。客户端不使用环境代理且拒绝跟随重定向，避免意外转发令牌。当前终端依赖操作系统账户的访问控制，不能用于共享网络或未知说话人控制入口。

### 验证

```sh
python3 -m unittest discover -s tests -v
```

测试覆盖配置、人格校验与一致性、手动快照保存／恢复／删除、默认不落盘、模型状态检查、错误反馈、设备白名单及确认、本地知识与引用、候选规则，以及换事实／换规则和四种求值结果。独立 CLI 进程验证跨进程知识检索、会话恢复和离线规则；模型及设备接口仍使用模拟服务。

当前优先的实机验收：`/status` 确认模型存在；用同一话题进行多轮交流，核对人格和上下文；确认保存快照后重启恢复，取消恢复则不改变当前聊天；核对切换人格和 `/reset` 清空上下文。模型服务未启动时，这些真实生成效果不标记完成。

以后接入设备时另行验收：查询一个已授权灯或风扇，分别验证取消和确认开关操作；尝试未授权实体应被拒绝。没有装修或真实设备不阻塞人格和聊天开发。

## 核心目标

- **人格与交流**：具有可配置的名字、表达风格和行为边界，支持连续对话。
- **设备管理**：查询和控制家中的智能设备，逐步支持场景与自动化。
- **日常问答**：支持聊天与知识问答；需要实时信息时明确说明联网需求和信息来源。
- **成员识别**：经成员同意录入声纹，区分已登记成员与未知说话人；不确定时保持未知身份。
- **个性化记忆**：按成员隔离保存经确认的偏好和习惯，支持查看、修改、删除及暂停记忆。
- **本地优先**：优先在本地处理语音、对话和记忆；任何外部服务接入都应明确告知数据流向。

## 当前架构与后续边界

```text
可信本地终端
   |
   +-- 普通聊天 --> 本地模型 + 当前人格 + 最近 10 轮上下文
   |                  ↕ 显式确认保存／恢复
   |              独立本地会话快照（默认不保存）
   +-- /ask --> 本地词法检索 --> 隔离的证据问答 + 引用校验
   +-- /propose --> 模型生成候选规则 --> schema 校验 --> 人工核对
   +-- /reason --> 外部规则 + 外部事实 --> 独立求值 + 解释
   +-- 显式设备命令 --> 白名单 + 二次确认 --> Home Assistant

后续：成员认证与私有知识隔离、语音、规则审批、专用模型研究
```

候选集成方向：

- **设备网关**：优先评估 Home Assistant，统一接入设备，避免直接耦合不同厂商协议。
- **模型运行时**：评估 Ollama 等本地运行方案，依据电脑配置选择模型。
- **语音链路**：分别评估本地语音识别、说话人验证和语音合成组件；语音转文字本身不能证明说话人身份。
- **记忆存储**：优先评估 SQLite，先实现结构化偏好，再根据需要扩展对话检索。

当前已实现 Ollama、Home Assistant 客户端接口和 SQLite 文档库；尚未验证真实模型与设备。语音组件和成员偏好存储仍待实施。

## 安全与隐私边界

- 声纹不作为唯一认证方式：录音重放、相似声音和识别错误都可能导致误判。
- 未知说话人默认不能读取成员私人记忆或操作设备；可提供不涉及隐私的普通问答。
- 门锁、安防、支付等高风险操作需要独立确认或额外认证，不能仅凭模型输出或声纹执行。
- 模型只能提出操作意图，实际执行必须经过确定性的权限检查、参数校验和设备白名单。
- 成员声纹、原始音频和个人记忆按需采集；默认不长期保留原始音频。
- 习惯推断应与成员确认，不能把一次对话或临时要求直接认定为长期偏好。
- 提供数据保留、撤回授权和删除机制；日志避免记录密钥、原始声纹和私人对话内容。
- 凭据不进入版本控制；离线状态、服务不可用和设备执行失败必须明确反馈。

## 分阶段开发

1. **文字最小闭环**：本地聊天、人格配置、Home Assistant 设备查询与低风险控制、权限检查。
2. **外挂知识与显式规则**：来源检索、证据问答、独立规则求值和候选规则生成，建立研究基线。
3. **家庭成员与记忆**：成员授权、身份验证、未知身份处理、知识隔离、偏好确认与删除。
4. **语音交互**：麦克风输入、本地语音转文字、语音回复，以及打断和错误提示。
5. **习惯辅助与研究迭代**：规则审批、自动化确认与撤销，以及评测驱动的专用模型实验。

## 开发前需要确认

- 本地电脑的操作系统、内存、GPU 和常驻运行条件。
- 已有设备品牌、协议，以及是否已经部署 Home Assistant。
- 是否要求完全离线，以及是否允许可选的联网问答。
